==============================================================================
OVERVIEW                                                  *gutenberg-overview*

gutenberg is a library of composable APIs for editing markdown, built on
treesitter. It ships no keymaps and no commands — it provides the
primitives to build your own:
>lua
  local list = require('gutenberg.api').list

  if list.is_list_item() then
    local item, node = list.read()
    list.set_checked(item, not list.is_checked(item))
    list.replace(node, { item })
  end
<
Or, using the verb tier that composes that loop for you:
>lua
  require('gutenberg').list.toggle_checkbox()
<
Where to go next:

  New here?             `:lua require('gutenberg').tour()`   |gutenberg.tour|
  Bind some keymaps     |gutenberg-recommended-config|
  Learn the shape       |gutenberg-design|, |gutenberg-recipes|
  Full reference        |gutenberg-api|
  Something's broken    `:checkhealth gutenberg`         |gutenberg-health|

==============================================================================
SETUP                                                        *gutenberg.setup*

Optional — gutenberg works out of the box. Call `setup` to change the
defaults listed in |gutenberg.config|, or to opt into the recommended
keymaps (|gutenberg-recommended-config|):
>lua
  require('gutenberg').setup{
    default_keymaps = { enable = true },
    list = { default_checked = false },
  }
<
The root module lazily resolves every submodule, so
`require('gutenberg').list` is equivalent to requiring the module
directly but defers the cost until first use. Nothing loads at startup
for features you don't touch.

==============================================================================
DESIGN                                                      *gutenberg-design*

Everything gutenberg exposes is one of three kinds of function:

- Interpretation — answer questions about the document without changing
  it: the `is_*` probes, `read`, `get_*` accessors,
  |gutenberg.api.link.resolve()|, |gutenberg.api.table.column_at()|.
- Navigation — locate constructs. |gutenberg.api.heading.list()| and
  the `find_*` family return values and nodes and never move the
  cursor; the root-level motions (|gutenberg.heading.next()|,
  |gutenberg.table.next_cell()|, …) exist to be bound as motions and
  DO move it.
- Codemods — produce text or change the buffer: `create` / `render`
  build text from values, `set_*` mutate values in memory, `replace`
  writes back in a single update, and the verbs (`update`,
  `toggle_checkbox`, `promote`, `format`, …) compose the whole loop.

The API is split in two tiers along those seams:

- `require('gutenberg.api')` holds the low-level per-construct
  primitives — probes, read / create / render / replace, accessors,
  navigation. Nothing here prompts, notifies, or moves the cursor.
- `require('gutenberg')` holds the verbs — count- and range-aware,
  with UI-ready error messages, designed to be bound
  through |gutenberg.keymap|.

Every api module shares one surface built from those kinds:

  `is_*({ctx})`          probe the cursor
  `read({ctx})`          decode the node into a plain value
  getters / setters    inspect and mutate the value in memory
  `create({fields})`     build a value from scratch
  `render(value)`        turn a value back into text
  `replace(node, …)`     write it to the buffer in one update

and every root module adds the composed loop on top, starting with
`update(fn, {ctx})`: read → `fn` → replace in one call.

Transforms stay in memory until the final write, so a multi-step edit
is one buffer write and one undo entry — bulk verbs included. No-op
writes are skipped entirely and never pollute undo history.

CONTEXT                                                    *gutenberg.context*

Nothing assumes the current buffer or cursor. Every cursor-relative
function takes an optional context table and defaults missing fields to
the current buffer and window cursor:
>lua
  ---@class gutenberg.Context.Partial
  ---@field bufnr? integer
  ---@field cursor? [integer, integer]  -- {row (1-indexed), col (0-indexed)}
  ---@field count? integer              -- defaults to 1
  ---@field range? gutenberg.Range
<
Pass `{ bufnr = ... }` to drive edits in background buffers, or a full
`{ bufnr, cursor }` for fully programmatic rewrites.

`count` scales the verbs the way a keymap count would: promote N
levels, toggle N items, jump N headings. It is never read from
|v:count1| — the keymap edge passes it explicitly (|gutenberg.keymap|
does that for you).
                                                              *gutenberg.Range*
`range` targets a span instead of the cursor — the library-level shape
of a visual selection:
>lua
  ---@class gutenberg.Range
  ---@field mode 'line' | 'char'
  ---@field start [integer, integer]  -- inclusive {row (1-idx), col (0-idx)}
  ---@field stop [integer, integer]   -- inclusive; col ignored for 'line'
<
Ranges are normalized on resolve: swapped endpoints flip, line-mode
columns zero, and charwise stops widen to whole characters when text is
read or written. When a range is given without a cursor, the cursor
defaults to the range start, so `is_*` probes gate range-driven calls
for free. Build one from the last visual selection with
`context.range_from_visual({bufnr})`, or let |gutenberg.keymap.visual()|
hand you the live one.

TOUR                                                          *gutenberg.tour*

An interactive tour of the plugin, in the spirit of |:Tutor|:
>lua
  require('gutenberg').tour()
<
This opens a scratch copy of the tour document — edit anything, nothing
is saved — with the keymaps from |gutenberg-recommended-config| bound
to that buffer alone. Undo bottoms out at the pristine document, and
reopening replaces the buffer with a fresh copy. Returns the tour
buffer number.

RECIPES                                                    *gutenberg-recipes*

The verbs are designed to be bound. |gutenberg.keymap| supplies
the adapters — dot-repeat, counts, operators, live visual ranges — and
the notify edge, so a binding is one line per mode. Two tiny glue
helpers cover almost everything (the same helpers the recommended
config is built from):
>lua
  local gutenberg = require('gutenberg')
  local keymap = gutenberg.keymap

  -- A cursor motion: count-aware, usable as an operator target.
  local function motion(lhs, fn, desc)
    vim.keymap.set({ 'n', 'x', 'o' }, lhs, function()
      keymap.notify(function()
        fn({ count = vim.v.count1 })
      end)
    end, { buffer = true, desc = 'gutenberg: ' .. desc })
  end

  -- An edit: count + `.`-repeat in normal mode, bulk over the
  -- selection in visual mode.
  local function edit(lhs, fn, desc)
    vim.keymap.set('n', lhs, keymap.repeatable(fn), {
      buffer = true,
      expr = true,
      desc = 'gutenberg: ' .. desc,
    })
    vim.keymap.set('x', lhs, keymap.visual(fn), {
      buffer = true,
      desc = 'gutenberg: ' .. desc,
    })
  end

  motion(']h', gutenberg.heading.next, 'next heading')
  edit('<leader>mx', gutenberg.list.toggle_checkbox, 'toggle checkbox')
<
With that, `3]h` jumps three headings, `d]h` deletes to the next one,
a visual `<leader>mx` bulk-toggles the selection, and `.` repeats —
count included.

Semantically related actions can share one binding and dispatch on
what's under the cursor — the `is_*` probes make the gate a two-line
branch, and a resolved range defaults the cursor to its start so the
same gate works in visual mode:
>lua
  edit('<leader>m<', function(ctx)
    if gutenberg.api.heading.is_heading(ctx) then
      gutenberg.heading.promote(ctx)
    elseif gutenberg.api.list.is_list_item(ctx) then
      gutenberg.list.dedent(ctx)
    elseif gutenberg.api.table.is_table(ctx) then
      gutenberg.table.move_column_left(ctx)
    else
      error('gutenberg: nothing under the cursor to shift left', 0)
    end
  end, 'promote heading / dedent item / move column left')
<
Behaviors without a dedicated verb compose from `update`, which reads
the construct at the cursor, applies your function, and writes back in
a single update:
>lua
  -- Uppercase the heading under the cursor.
  local heading = gutenberg.api.heading
  gutenberg.heading.update(function(h)
    heading.set_text(h, heading.get_text(h):upper())
  end)
<
And anything `update` can't express drops down one layer to the same
primitives it is built from:
>lua
  -- Renumber ordered siblings after moving a line.
  local list = gutenberg.api.list
  gutenberg.list.update_list(function(entries)
    for i, entry in ipairs(entries) do
      if list.is_ordered(entry.item) then
        list.set_marker(entry.item, i .. '.')
      end
    end
  end)
<

RECOMMENDED CONFIG                              *gutenberg-recommended-config*
                                                    *gutenberg.default_keymaps*
A complete starting point, off by default. Opt in through
|gutenberg.setup|:
>lua
  require('gutenberg').setup{
    default_keymaps = {
      enable = true,
      -- The default scope; pass your own list to change it.
      filetypes = { 'markdown', 'markdown.mdx', 'mdx' },
    },
  }
<
This binds the maps below to every matching buffer — buffer-locally, on
|FileType|, nothing global. Failures surface as notifications, and
every edit gets counts, visual mode, and `.`-repeat:

  Motions (n, x, o — count-aware, operator-friendly) ~
    ]E  [E        next / previous table
    ]e  [e        next / previous table cell
    i|            inner table cell textobject (x, o)
    ]c  [c        next / previous unchecked item
    ]C  [C        next / previous checked item

  Edits (n with count + `.`, x over the selection) ~
    <leader>m<    promote heading / dedent list item / move column left
    <leader>m>    demote heading / indent list item / move column right
    <leader>mx    toggle checkbox (visual: bulk check/uncheck)
    <leader>mX    remove checkbox (visual: over the selection)
    <leader>ma    toggle list ordered / cycle column alignment

  Insert siblings (n) ~
    <leader>mo    append list item / table row below, then insert
    <leader>mO    prepend list item / table row above, then insert

  Tables ~
    <leader>mf    format table
    <leader>mt    column actions picker (insert left/right, delete)

  Inline spans (wrap: n motion / x selection; capital: remove at cursor) ~
    <leader>ml    wrap in a link; prompts for the URL — empty is fine,
                  `[text]()` is legal
    <leader>mL    remove the link under the cursor (`.`-repeatable)
    <leader>me <leader>mE    emphasis    `_x_`   (delimiter configurable)
    <leader>mb <leader>mB    strong      `**x**` (delimiter configurable)
    <leader>ms <leader>mS    strikethrough  `~~x~~`
    <leader>mc    charwise: wrap an inline code span `` `x` ``;
                  linewise: fence a code block
    <leader>mC    remove the code span under the cursor (`.`-repeatable)

Built into Neovim already, so this config leaves them alone: the
markdown |ft-markdown-plugin| binds `]]` / `[[` to jump between
sections (heading navigation) and `gO` to open a section outline.

Link EDITING has no binding on purpose: the URL and text of
`[text](url)` are plain delimited text, so builtin `ci(` and `ci[`
already edit them.

The bindings live in `lua/gutenberg/default_keymaps.lua`, written to be
read: every map is a verb (or an `is_*` dispatch across verbs) wrapped
in a |gutenberg.keymap| adapter, built from the same two glue helpers
as |gutenberg-recipes|. It doubles as the reference implementation —
to change a binding, leave `enable` off and copy what you want into
your own |FileType| autocmd.

Buffers that already carry a matching filetype when `setup` runs are
bound immediately, so plugin managers that load gutenberg lazily on
the |FileType| event work without ceremony.

                                            *gutenberg.default_keymaps.apply()*
apply({bufnr})
    Bind the full recommended set into {bufnr}, buffer-locally. This is
    what the |FileType| autocmd calls and what |gutenberg.tour| applies
    to its scratch buffer. Use it to adopt the whole set in buffers the
    `filetypes` list can't describe.

KEYMAP HELPERS                                                *gutenberg.keymap*

Adapters that turn the verbs into well-behaved keymaps: dot-repeat,
counts, operators, and visual mode. gutenberg still ships no keymaps —
your mappings consume these. This module is a sanctioned UI edge: every
adapter runs its callback under |pcall()| and surfaces failures through
|vim.notify()| at WARN.

notify({fn})                                        *gutenberg.keymap.notify()*
    Run {fn}, notifying on error instead of throwing. The escape hatch
    for one-off mappings (motions, pickers) that need no other
    adapter.

repeatable({fn})                                *gutenberg.keymap.repeatable()*
    Wrap a verb as a dot-repeatable, count-aware normal-mode
    edit. Returns a function for an `expr = true` mapping: >lua
      vim.keymap.set('n', '<leader>m>', keymap.repeatable(function(ctx)
        require('gutenberg').heading.demote(ctx)
      end), { expr = true })
<
    {fn} receives `{ count = vim.v.count1 }`. The count is read inside
    the |operatorfunc| trampoline, so `3<lhs>`, |.|, and `5.` all
    deliver the right count. Known caveat: the `g@l` trampoline no-ops
    on empty lines.

operator({fn})                                    *gutenberg.keymap.operator()*
    Wrap a verb as an operator: the mapping waits for a motion
    or textobject and hands {fn} the covered range as
    `{ range = ... }` (an inclusive char or line range). Returns a
    function for an `expr = true` mapping. Dot-repeat comes free with
    |g@|. Blockwise-forced motions notify and do nothing.

visual({fn})                                        *gutenberg.keymap.visual()*
    Wrap a verb as a visual-mode edit. Reads the LIVE selection
    (|getpos()| on `'v'` and `'.'` — the `'<` / `'>` marks still
    describe the previous selection while visual mode is active),
    normalizes backwards selections, leaves visual mode, then calls
    {fn} with `{ range = ... }`. Blockwise selections notify and do
    nothing.

ERRORS                                                      *gutenberg-errors*

gutenberg never calls |vim.notify()|. Functions throw, and the binding
edge decides whether a failure is user-facing — the same API must serve
interactive keymaps and silent programmatic rewrites, and only the
caller knows which one it is.

Three sanctioned exceptions carry that edge for you: the
|gutenberg.keymap| adapters pcall their callbacks and notify at WARN,
the recommended keymaps (|gutenberg.default_keymaps|, shared by the
|gutenberg.tour| buffer) ride those adapters and prompt for link URLs,
and |gutenberg.table.actions()| notifies from its prompt callbacks (its
off-table error still throws synchronously). Everything else stays
headless.

Errors fall into two classes:

- Contract violations: calling `read` without gating on the `is_*`
  probe, invalid arguments (|gutenberg.api.heading.set_level()| outside
  1..6, bad cell indices), or a broken install (missing
  |gutenberg-queries| files). These indicate a bug in the calling code
  or the setup; fix the code.
- Inapplicable operations: a correctly-gated action that doesn't apply
  to the value under the cursor — |gutenberg.api.list.dedent()| on an
  unindented item, or `set_url` on a `reference_*` link
  (|gutenberg.api.link-accessors|). These are expected at the keymap edge;
  wrap them in `pcall` and surface the message.

Messages are prefixed with `gutenberg:` and thrown without position
information (|error()| level 0), so the string `pcall` returns is ready
for |vim.notify()| verbatim. Transforms validate before writing: a
failed operation never leaves a half-edited buffer or a stray undo
entry.

==============================================================================
HEALTH                                                      *gutenberg-health*

If something misbehaves — probes that never match, keymaps that do
nothing — start here: >vim
  :checkhealth gutenberg
<
It verifies the pieces gutenberg depends on at runtime:

- A supported Neovim (0.10 or newer).
- The `markdown` and `markdown_inline` treesitter parsers. Neovim
  bundles both since 0.10, but distributions and plugin managers can
  shadow them with older builds.
- The |gutenberg-queries| files: present on 'runtimepath', compiling
  against the installed grammar version (a compile failure means the
  parser is older or newer than the query expects), and still defining
  every capture the modules need (a user query that replaces ours
  instead of extending it fails loudly here).

==============================================================================
QUERIES                                                    *gutenberg-queries*

The nodes each module recognizes are declared in |treesitter-query|
files shipped with the plugin: >
  queries/markdown/gutenberg.scm          block constructs
  queries/markdown_inline/gutenberg.scm   inline constructs
<
Each capture names a construct: `@heading`, `@code_block`,
`@list_item`, `@table`, `@link_definition`, and the inline `@link`,
`@emphasis`, `@strong`, `@strikethrough`, and `@code_span`. To teach a
module additional node types, place an extending query on your
'runtimepath': >query
  ;; extends

  (setext_heading) @heading
<
in `~/.config/nvim/queries/markdown/gutenberg.scm`. Recognition is
extensible this way; decoding is not — `read` still only understands
the built-in node shapes, so probes like `is_heading` accept extended
nodes while `read` may error on them.

Inline `@link` patterns must also declare which |gutenberg.link.Kind|
the node decodes as: >query
  ;; extends

  ((email_autolink) @link
    (#set! kind "autolink"))
<
==============================================================================
API                                                              *gutenberg-api*

Two tiers per construct. The root modules (`require('gutenberg').list`)
carry the verbs: count- and range-aware, with UI-ready errors,
meant for keymaps. `require('gutenberg.api').list` carries the
primitives the verbs are built from. Value types
(`gutenberg.list.Item`, `gutenberg.table.Table`, …) are shared by both
tiers.

------------------------------------------------------------------------------
LIST                                                            *gutenberg.list*

Read and edit markdown list items. A list item is one row of bullet
(`-`, `*`, `+`) or ordered (`1.`) marker plus optional checkbox and
text. Nested items are themselves `list_item` nodes inside a child
`list`.

A `gutenberg.list.Item` is a plain table: >lua
    {
      indent = '',     -- leading whitespace before the marker
      marker = '-',    -- '-', '*', '+', or e.g. '1.'
      checkbox = nil,  -- nil, ' ', 'x', or any single-char state
      text = 'foo',    -- content after marker (and checkbox, if present)
    }
<
Verbs — `require('gutenberg').list`:

update({fn}, {ctx})                                   *gutenberg.list.update()*
    Read the item at the cursor, apply {fn}, and write the result back
    in a single buffer update. {fn} may mutate the item in place (and
    return nothing) or return a replacement list — return `{}` to
    delete the item. Returns the written items. Errors when the cursor
    isn't on a list item.

update_list({fn}, {ctx})                         *gutenberg.list.update_list()*
    Read the cursor item's direct siblings, apply {fn} to the entries,
    and rewrite their marker rows in one buffer update. {fn} mutates
    each entry's `item` in place; entries cannot be added or removed.
    Errors when the cursor isn't on a list item.

toggle_checkbox({ctx})                       *gutenberg.list.toggle_checkbox()*
    Toggle the checkbox on the item at the cursor: bare items gain one
    in the configured state (`gutenberg.list.Config.default_checked`),
    checkboxed items flip. With a range, toggles every item inside it
    as a group — if any target is unchecked or bare, all become
    checked, otherwise all become unchecked — in one buffer update.
    Counts are ignored: "toggle 3 checkboxes" has no coherent meaning,
    so bulk toggles come from ranges (visual mode at the keymap edge).

remove_checkbox({ctx})                       *gutenberg.list.remove_checkbox()*
    Strip the checkbox from the item at the cursor, turning a task item
    back into a plain list item; items without one are left untouched.
    With a range, strips every targeted item in one buffer update.
    Errors when the cursor isn't on a list item (or the range holds
    none).

toggle_ordered({ctx})                         *gutenberg.list.toggle_ordered()*
    Switch the item at the cursor between ordered and unordered. With
    a count or range, switches every target in the direction of the
    first one, renumbering newly ordered runs from 1, in one buffer
    update.

toggle_ordered_list({ctx})               *gutenberg.list.toggle_ordered_list()*
    Switch the cursor item and all of its direct siblings between
    ordered and unordered, renumbering from 1 when switching to
    ordered. The direction comes from the first sibling.

insert_item({opts}, {ctx})                       *gutenberg.list.insert_item()*
    Insert a blank sibling next to the item at the cursor, cloning its
    indent and marker (and an unchecked checkbox when the cursor item
    has one), then renumber every ordered sibling group so the new item
    counts in. `opts.where` is `'below'` (default; past the item's
    nested children) or `'above'`. One buffer update. Unlike most
    codemods it moves the window's cursor onto the new item — its
    rendered marker carries a trailing space, so a following
    |startinsert!| lands ready for text entry. Errors when the cursor
    isn't on a list item.

indent({ctx})                                         *gutenberg.list.indent()*
dedent({ctx})                                         *gutenberg.list.dedent()*
    Nest the item at the cursor under its previous sibling / lift it
    out to its enclosing item's level. Both derive the shift from the
    document, not just an indent width: `indent` moves the item at
    least `count` units (|gutenberg.api.list.indent_unit()|) and always
    far enough to reach the sibling's content column, so `3.` nests
    under `2.` even when the unit is narrower than the marker; `dedent`
    strips down to the `count`-th enclosing item's column, clamped at
    the outermost. Nested children move with the item, and every
    ordered sibling group in the affected list is renumbered — the old
    siblings close the gap the item left, its new siblings count it
    in, `.` vs `)` delimiters survive. One buffer update. With a
    range, shifts each selected item whose parent item isn't also
    selected (children travel with their parent).

    Both refuse before writing when the move is undefined, so a run of
    indents is reversed exactly by the same run of dedents: `indent`
    when the item has no previous sibling to nest under (nesting is
    defined only relative to one — otherwise it would pile on
    whitespace until the item stopped parsing as a list), `dedent` when
    the item is already top-level or a line lacks the whitespace to
    strip. For a plain one-unit text shift with no renumbering or
    guard, use the |gutenberg.api.list.indent()| primitive.

next_checkbox({ctx}, {opts})                 *gutenberg.list.next_checkbox()*
prev_checkbox({ctx}, {opts})                 *gutenberg.list.prev_checkbox()*
    Move the cursor to the `count`-th list item after / before it —
    these are motions and DO move the current window's cursor, unlike
    everything in `gutenberg.api`. Overshooting counts clamp to the
    furthest match; no match at all leaves the cursor alone and returns
    nil. {opts} takes the `checked` filter of
    |gutenberg.api.list.find_next()|: `{ checked = false }` walks
    unchecked items, `{ checked = true }` walks checked ones, and no
    filter walks every list item. The recommended keymaps bind these to
    `]c` / `[c` (unchecked) and `]C` / `[C` (checked).

Primitives — `require('gutenberg.api').list`:            *gutenberg.api.list*

is_list_item({ctx})                         *gutenberg.api.list.is_list_item()*
    Whether the cursor is on a list item. Gate calls to `read` with
    this.

read({ctx})                                         *gutenberg.api.list.read()*
    Read the item containing the cursor. Returns
    `(gutenberg.list.Item, TSNode)`; pass the node to `replace`.
    Errors when the cursor isn't on a list item.

create({fields})                                  *gutenberg.api.list.create()*
    Build an item from `{ indent?, marker?, checkbox?, text? }`.
    Missing fields fall back to |gutenberg.list.Config| (default
    `marker = '-'`).

render({item})                                    *gutenberg.api.list.render()*
    Render an item to a single line of buffer text.

replace({node}, {items}, {ctx})                  *gutenberg.api.list.replace()*
    Replace {node}'s marker row with the rendered {items} in a single
    buffer update. Pass an empty list to delete the item.

items({ctx})                                       *gutenberg.api.list.items()*
    Every list item in the buffer — any list, any depth — in document
    order, as `{ item, node }` entries.

find_next({ctx}, {opts})                       *gutenberg.api.list.find_next()*
find_prev({ctx}, {opts})                       *gutenberg.api.list.find_prev()*
    The nearest list item strictly after / before the cursor row,
    returned as `(gutenberg.list.Item, TSNode)`, or nil when none
    qualifies. {opts} is an optional table with a `checked` filter: set
    it to keep only items in that checked state — items without a
    checkbox never match a boolean filter. Neither moves the cursor; the
    root-level |gutenberg.list.next_checkbox()| motions build on these.

prepend({node}, {items}, {ctx})                  *gutenberg.api.list.prepend()*
append({node}, {items}, {ctx})                    *gutenberg.api.list.append()*
    Insert the rendered {items} as new siblings directly above / below
    {node} (a `list_item`); `append` lands past the node's nested
    children. Single buffer update; an empty {items} list is a no-op.

insert({list_node}, {index}, {items}, {ctx})      *gutenberg.api.list.insert()*
    Insert the rendered {items} into {list_node} (see `read_list`) so
    the first lands at position {index} among the list's direct items.
    An index past the last item appends to the end of the list. Errors
    when {index} is not a positive integer.

read_list({ctx})                               *gutenberg.api.list.read_list()*
    Read every direct sibling of the cursor's item. Returns
    `({ item, node }[], list_node)` in document order. Write the
    entries back with `replace_items`; the `list_node` is the parent
    `list` TSNode for `insert`. Errors when the cursor isn't on a
    list item.

replace_items({entries}, {ctx})            *gutenberg.api.list.replace_items()*
    Rewrite the marker rows of each entry in a single buffer update.
    Nested children are preserved verbatim. Entries may come from
    `read_list`, `items`, or any subset of either. Use to switch
    markers across siblings (e.g. unordered → ordered): `read_list`,
    mutate each entry's `item` with `set_marker`, then
    `replace_items`.

renumber({items})                               *gutenberg.api.list.renumber()*
    Renumber ordered markers in {items} sequentially from 1, in place

INLINE SPANS                                          *gutenberg-inline-spans*

Wrap and unwrap the four delimited inline constructs. They share one
surface, parameterized only by their delimiters: >
    module          reads          wrap / render emits
    emphasis        *x* or _x_      _x_  (configurable)
    strong          **x** or __x__  **x**  (configurable)
    strikethrough   ~~x~~           ~~x~~
    code_span       `x`             backticks (auto-escalated + padded)
<
`emphasis` and `strong` emit the delimiter configured under
|gutenberg.emphasis.Config| / |gutenberg.strong.Config| — prettier's `_`
and `**` by default. `read` accepts either spelling regardless; only
`render` (and the verbs and `replace` that build on it) picks a side.
A value is a plain table `{ text = '...' }`: the visible text with the
delimiters stripped (and, for code spans, CommonMark padding removed).
`read` resolves the OUTERMOST node, so it round-trips the grammar's
nesting — `emphasis` on `***x***` reads `**x**`, `strong` reads `x`,
and `~~x~~` (parsed as nested strikethroughs) reads `x`.

    range is charwise and on a single line.

CONFIG                                                      *gutenberg.config*

|gutenberg.setup| accepts a `gutenberg.Config` table. Defaults:
>lua
  {
    default_keymaps = {
      enable = false,          -- bind the recommended keymaps
      filetypes = { 'markdown', 'markdown.mdx', 'mdx' },
    },
    list = {
      marker = '-',            -- bullet for new/unordered items
      indent = nil,            -- indent unit; nil = derive from buffer
      default_checked = true,  -- state of a newly-inserted checkbox
    },
    heading = {
      level = 1,               -- default level for created headings
    },
    table = {
      default_alignment = 'none',
    },
    code_block = {
      fence = '`',             -- '`' or '~'
      fence_length = 3,        -- >= 3
    },
    link = {
      default_kind = 'inline', -- kind used when create() omits one
    },
    emphasis = {
      delimiter = '_',         -- '_' or '*'
    },
    strong = {
      delimiter = '**',        -- '**' or '__'
    },
  }
<
                                             *gutenberg.default_keymaps.Config*
`default_keymaps.enable`  Bind the recommended keymaps
                        (|gutenberg-recommended-config|) on |FileType|.
                        Off by default — gutenberg ships no keymaps
                        unless asked.
`default_keymaps.filetypes` Filetypes to bind in. A dotted compound
                        filetype matches the full 'filetype' value,
                        hence the explicit `markdown.mdx` entry in the
                        default. Passing a list replaces the default
                        wholesale.

                                                       *gutenberg.list.Config*
`list.marker`             Default bullet marker for new items.
`list.indent`             Whitespace unit for |gutenberg.api.list.indent()| /
                        |gutenberg.api.list.dedent()|, and the minimum
                        shift for |gutenberg.list.indent()| (which
                        widens as needed to actually nest). When nil
                        (default), derived per call from the target
                        buffer's 'expandtab' and 'tabstop'.
`list.default_checked`    State of a newly-inserted checkbox, used by
                        |gutenberg.list.toggle_checkbox()| when
                        promoting a bare item.

                                                    *gutenberg.heading.Config*
`heading.level`           Default level for new headings (1..6).

                                                      *gutenberg.table.Config*
`table.default_alignment` |gutenberg.table.Alignment| for new tables.

                                                 *gutenberg.code_block.Config*
`code_block.fence`        Default fence character for new blocks.
`code_block.fence_length` Default fence length (>= 3).

                                                       *gutenberg.link.Config*
`link.default_kind`       |gutenberg.link.Kind| used when
                        |gutenberg.api.link.create()| omits one.

                                                   *gutenberg.emphasis.Config*
`emphasis.delimiter`      Delimiter |gutenberg.api.emphasis.render()| wraps
                        emphasized text in. Prettier's `_` by default;
                        `*` is the common alternative. `read` still
                        accepts either spelling.

                                                     *gutenberg.strong.Config*
`strong.delimiter`        Delimiter |gutenberg.api.strong.render()| wraps
                        strong (bold) text in. Prettier's `**` by
                        default; `__` is the alternative. `read` still
                        accepts either spelling.
